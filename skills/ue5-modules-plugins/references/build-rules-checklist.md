# Build Rules Checklist

## ModuleRules

- Start from a module generated by the target Engine version.
- Keep `PublicDependencyModuleNames` limited to types exposed by Public headers.
- Keep implementation dependencies private.
- Add editor dependencies only when `Target.bBuildEditor` is not enough to prevent a Runtime reference; prefer a dedicated Editor module.
- Do not add Engine private include paths.
- Do not set RTTI/exceptions globally to solve one third-party integration without reviewing ABI and platform impact.
- Pin intended build/include settings for cross-version plugins; avoid `Latest`.

## Descriptor

- Module `Type` matches Runtime/Editor/Developer/Program use.
- Loading phase matches registration requirements.
- Platform and Target allow-lists are explicit only when needed.
- Plugin dependencies are declared, not assumed because another plugin happens to be enabled.
- Experimental/Editor-only capabilities do not leak into packaged Runtime.

## Link/load errors

Check symbol implementation, API export macro, owning module dependency, matching configuration, stale binary, plugin enabled state, and module startup log—in that order.
